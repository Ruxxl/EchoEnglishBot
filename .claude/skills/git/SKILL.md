# /git — сравнить с GitHub, закоммитить и запушить в main

Пользователь вызвал `/git`, значит, коммит и пуш в `main` для этого запуска разрешены. Отвечай пользователю по-русски.
Если передан аргумент (`$ARGUMENTS`), используй его как сообщение коммита, иначе составь его сам.

## 1. Сравнить локальный проект с GitHub

```bash
git fetch origin
git branch --show-current
git status -sb
git rev-list --left-right --count main...origin/main   # слева — локальные коммиты, справа — коммиты на GitHub
git log --oneline origin/main..main                    # не запушено
git log --oneline main..origin/main                    # есть на GitHub, нет локально
git status --short -uall                               # незакоммиченные и новые файлы
```

Коротко покажи пользователю: сколько коммитов не запушено, сколько есть только на GitHub, какие файлы изменены, удалены или новые.

- Если текущая ветка не `main`, остановись и спроси, что делать.
- Если всё совпадает и изменений нет, скажи «Локальный проект совпадает с GitHub, пушить нечего» и закончи.

## 2. Проверить, что уходит на GitHub

Перед коммитом прочитай `git diff` и посмотри список новых файлов. Не коммить и предупреди пользователя, если среди них есть:

- `.env`, базы `*.db` / `*.sqlite3`, `uploads/`, `.venv/` — их не должно быть в репозитории (они в `.gitignore`);
- ключи и токены в тексте: `BOT_TOKEN`, `GEMINI_API_KEY`, `DEEPGRAM_API_KEY`, строки вида `sk-...`, `AIza...`, `<цифры>:<буквы>` (токен бота);
- большие бинарные файлы (видео, PDF, архивы больше ~5 МБ) — спроси, нужны ли они в репозитории;
- папки результатов вроде `brag-output/`.

Файлы пользователя не удаляй и не откатывай: если сомневаешься, спроси.

## 3. Подтянуть изменения с GitHub, если они есть

Если на GitHub есть коммиты, которых нет локально:

```bash
git pull --rebase origin main
```

При конфликте остановись, покажи конфликтующие файлы и спроси пользователя. Не используй `--force` и не делай `git reset --hard`.

## 4. Закоммитить и запушить

```bash
git add -A
git commit -m "<сообщение>"
git push origin main
```

Сообщение коммита — на английском, в стиле истории проекта (`git log --oneline -10`): первая строка про суть изменения, ниже по желанию пара строк «почему». В конце добавь строку соавторства, которую требует текущая сессия Claude Code.

Если незакоммиченных изменений нет, но есть незапушенные коммиты, просто сделай `git push origin main`.

## 5. Итог

Покажи хеш и заголовок нового коммита, результат `git push`, затем ещё раз `git status -sb` и `git rev-list --left-right --count main...origin/main`. Должно получиться `0 0` и чистая рабочая копия. Напомни, что Render сам задеплоит `main`, если у сервиса включён автодеплой.
